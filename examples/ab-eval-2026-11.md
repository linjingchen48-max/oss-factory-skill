# Controlled test: with and without the skill (2026-11-07)

## Setup

- 4 small command-line tasks × 2 conditions = 8 runs. Each run was a fresh agent with no shared
  context. It was not told it was being evaluated.
  - T1: CSV to formatted Excel (Python)
  - T2: batch image thumbnails (Node)
  - T3: Markdown to-do statistics (Python). The logic is simple enough that no dependency is needed.
  - T4: JSON Schema validation CLI (Node)
- Condition A got the task only. Condition B got the same prompt plus one sentence: read this
  skill and follow it. Both had to declare dependencies in a manifest, write and run tests, and
  report what they used.
- Same model, same machine (Windows 11, Python 3.11.9, Node 24.12.0). The optional engine was not
  available, so B measures the skill on its own.
- Grading happened after the runs: each project's own tests were rerun, its direct
  dependencies audited against deps.dev, and every tool run on shared tricky inputs. Those inputs
  and the expected answers were written down before any run started. Examples: fake to-dos inside
  a code fence, five nested schema errors, an upper-case `.JPG`, a non-image file, and a long
  Chinese column.

T3-A used no dependencies, so the dependency items did not apply to it; that is why A shows 0/3.

## Reading

- **Software quality did not differ.** All 8 tools were correct on the shared inputs, and neither
  condition introduced a critical dependency problem.
- **B wrote less of its own code** in all 4 tasks: −24% in total. T3 is the clearest case: B parsed
  with a Markdown library in 46 lines, while A used only the standard library in 108 lines and
  added no dependency. Both are reasonable choices.
- **Dependency health differed once.** In T1, A's runtime library had no release in over two years,
  while B's was actively released.
- **The steady difference is the paper trail.** B always recorded the candidates it considered,
  the reasons it gave for rejecting them, the licenses, and a resolver dry-run. A almost never did.
- **Cost:** about 11% more tokens and 12% more time.

## Caveats

- One run per cell. Model output varies, so a rerun could choose differently. This is not
  statistically significant.
- The tasks are small and have well-known libraries. Larger or vaguer projects were not tested.
- One model only.
- The grader is also the skill's author. To limit bias, the expected answers and the probe inputs
  were fixed before the runs.
- The test environment blocked agents from writing report files. Five runs worked around this
  through the shell; three put the report in their reply instead. The report itself was not scored.
